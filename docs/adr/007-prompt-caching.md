# ADR-007: Prompt caching — общий префикс «system + материал» для аналитиков, прогрев перед параллельным раундом

- **Status:** Accepted
- **Date:** 2026-10-11

## Context

После подъёма `MAX_TEXT_CHARS` до 200 000 символов (≈ 82k токенов) исходный текст стал
главной статьёй расходов. Он уходит в каждый вызов: 3 аналитика × число раундов, судья и
каждое сообщение чата с судьёй. На Opus 5.5 вход стоит $4 за 1M токенов, чтение из кэша —
$0,20 (0,05×), запись в кэш — 1,25× (TTL 5 минут) или 2× (TTL 1 час).

Кэш Anthropic совпадает по префиксу: `tools` → `system` → `messages`. До этого решения
префиксы были разными по двум причинам:

1. линза каждого аналитика лежала в его `system`, поэтому у трёх аналитиков три разных
   `system`;
2. текст шёл внутри user-сообщения после заголовка раунда («РАУНД 1 — …»), и заголовок
   менялся от раунда к раунду.

Ещё одно ограничение: параллельные запросы не видят кэш, который пишет соседний запрос.
Раунд 1 идёт тремя параллельными вызовами, и без подготовки каждый из них заплатил бы за
запись.

## Decision

1. **Один `system` на всех аналитиков**: Манифест и общая роль. Линза переезжает в начало
   задания (`AnalystSpec.lens`). Общий `system` говорит аналитику, что его линза названа в
   начале задания.
2. **Материал — отдельный блок перед заданием** (`ChatRequest.context`,
   `prompts.source_context`). Блок побайтно одинаков во всех вызовах одного разбора.
   Блок помечен `cache_control`, если в запросе задан `cache_ttl`.
3. **Прогрев перед раундом 1.** Порт `ChatProvider.prewarm` у Anthropic делает вызов с
   `max_tokens=0` и тем же префиксом и effort, что у настоящих запросов. Такой вызов
   пишет кэш и не тратит выходные токены. Ошибка прогрева только логируется.
4. **TTL:** у аналитиков 5 минут — вызовы идут подряд, и каждое чтение продлевает запись.
   В чате 1 час — пауза между сообщениями человека бывает больше 5 минут. В чате
   кэшируется блок «материал + транскрипт + вердикт», история переписки идёт после него.
5. **Судья без кэша.** Он вызывается один раз и с другим effort. Смена effort
   инвалидирует кэш сообщений, поэтому чтение из кэша аналитиков ему недоступно.
6. **DeepSeek** кэширует повторяющиеся префиксы сам. Ему материал и задание уходят одним
   сообщением в том же порядке; `prewarm` ничего не делает.
7. **`Usage.input_tokens` — весь промпт.** Закэшированная часть сюда входит, а
   `cache_read_tokens` и `cache_write_tokens` показаны отдельно. У API Anthropic
   `input_tokens` — только незакэшированный хвост, поэтому без пересчёта счётчик врал бы.

## Alternatives considered

- **Автоматическое кэширование** (`cache_control` верхнего уровня). Отвергнуто: точка
  кэша ставится на последний блок, то есть на уникальное задание. Каждый вызов платил бы
  за запись и ничего бы не читал.
- **Материал в `system`.** Отвергнуто: у судьи и чата свои `system`, общий префикс всё
  равно не получился бы. Кроме того, разобранный текст — это данные, а не инструкции
  оператора.
- **Mid-conversation system message для линзы.** Отвергнуто: такое сообщение должно идти
  последним или перед ответом ассистента, а после линзы нужно ещё задание с транскриптом.
- **Без прогрева, с последовательным стартом раунда 1** (дождаться первого токена одного
  аналитика и только потом запустить остальных). Отвергнуто: провайдер не стримит, а
  прогрев даёт тот же эффект без перестройки транспорта.

## Consequences

- Замер на живом API (2026-10-11, диалог 17 902 символа):
  - прогрев записал 8 871 токен за 1,8 с;
  - каждый следующий вызов аналитика прочитал эти 8 871 токен из кэша и ничего не
    записал;
  - часовой TTL записался (`ephemeral_1h`) и прочитался повторным запросом.
- **Оценка, не замер:** разбор в 2 раунда раньше платил за материал 7 раз по полной цене.
  Теперь — одна запись 1,25×, шесть чтений по 0,05× и полный вызов судьи: ≈ 2,55× вместо
  7×.
- Задание аналитика теперь стоит после материала, а не до него. Для длинных документов
  так и рекомендуется, но влияние на качество реплик не измерено (eval нет, см. ADR-002).
- В mock-режиме кэш не участвует; правильность раскладки держат unit-тесты на побайтное
  совпадение префикса.

## Revisit when

- Кэш перестанет попадать: `cache_read` в логах `llm.call` станет 0 у вызовов аналитиков.
- Поменяется модель судьи или его effort станет равен effort аналитиков — тогда судья
  сможет читать кэш аналитиков.
