# ADR-002: Три аналитика с общим Манифестом и разными методологическими линзами; слепой первый раунд; судья со структурированным вердиктом

- **Status:** Accepted
- **Date:** 2026-10-11

## Context

Требование: участники — «суперумные и рациональные все, не относящиеся ни к каким
философским течениям, апологеты рационального мышления»; критичны друг к другу, но
принимают рациональные ответы; судья решает, что самое рациональное. Первая версия имела
трёх философов-персонажей с характерами и лидерборд.

## Decision

1. Аналитики описаны **в коде** (`domain/analysts.py`), не в БД: три спеки с одинаковым
   системным Манифестом (7 столпов из скилла common-sense) и разной **линзой** — не школой:
   - 🔎 **Эмпирик** — факты, источники, бремя доказывания, проверяемость;
   - 🧩 **Логик** — структура аргумента, валидность, скрытые посылки, софизмы;
   - ⚖️ **Стилмен** — сильнейшая версия тезиса, альтернативные объяснения, Оккам,
     границы применимости.
   Линзы нужны, чтобы три вызова одной модели не дали три одинаковых ответа; при этом все
   трое подчинены одним правилам и одной цели — найти самое рациональное, а не победить.
2. **Раунд 1 слепой и параллельный**: аналитик не видит коллег — исключает якорение на
   первом ответе. Раунды 2+ последовательные с полным транскриптом и обязательными блоками
   «Принимаю / Оспариваю / Уточняю» (SPEC §4).
3. **Судья** — отдельный системный промпт, structured output по схеме `Verdict` (SPEC
   §3.3): заключение, rationality_score текста, статусы утверждений, софизмы, стилмен,
   критерий опровержения, so-what, оценки аналитиков.
4. Лидерборд и персоны в БД удалены: ценность истории — в самих разборах, а не в
   «победах» одинаковых агентов.

## Alternatives considered

1. **Три полностью идентичных агента.** Чище по букве требования; rejected: одна модель с
   одним промптом даёт почти одинаковые реплики — перекрёстная проверка вырождается.
2. **Оставить философов, но «рационализировать» промпты.** rejected: пользователь явно
   просит без течений; имена Ницше/Поппера сами по себе задают школу.
3. **Все раунды параллельные.** Быстрее; rejected: в перекрёстном раунде ценность — в
   реакции на уже сказанное в этом же раунде.
4. **Аналитики в БД (как было).** Редактирование без деплоя; rejected: промпты — часть
   поведения и должны быть в git рядом со SPEC; UI для их правки не в scope.

## Consequences

- Разбор = `3×rounds + 1` вызовов; при 2 раундах и Opus 5.5 — семь вызовов.
- Эффект линз не измерен; потребуется eval на наборе текстов (см. Revisit).

## Revisit when

- Eval покажет, что линзы дают < 2 различающихся позиций в раунде 1 на golden set.
- Понадобится ролевая настройка аналитиков пользователем — тогда вернуть хранение в БД.
