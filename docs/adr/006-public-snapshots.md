# ADR-006: Публикация разбора — статический снимок в публичном хранилище

- **Status:** Accepted
- **Date:** 2026-10-11

## Context

Пользователь хочет делиться разбором и вердиктом с кем угодно, у кого нет доступа к
приложению. Прод на Cloud Run закрыт IAP целиком: интеграция IAP с Cloud Run не умеет
исключать пути, поэтому ссылка вида `/s/<token>` на тот же сервис у постороннего человека
не откроется. Аутентификация и мультипользовательность — вне scope (SPEC §1), поэтому
снимать IAP ради одного маршрута нельзя.

## Decision

1. **Снимок, а не живая страница.** По кнопке «Опубликовать» сервер собирает одну
   самодостаточную HTML-страницу: стили инлайн, без JS и без обращений к API. Внутри
   исходный материал, реплики аналитиков и вердикт. Вердикт после `finished` не меняется
   (ADR-005, п. 4), поэтому снимок не устаревает, и повторная публикация отдаёт ту же
   ссылку.
2. **Порт `SnapshotPublisher`** (`publish(key, html) → url`, `unpublish(key)`), у него
   две реализации:
   - `GcsPublisher` (если задан `SHARE_BUCKET`) кладёт объект `<key>.html` в бакет. Бакет
     читается анонимно через `roles/storage.legacyObjectReader` для `allUsers`. Эта роль
     даёт только `objects.get` без `objects.list`, поэтому перечислить чужие публикации
     нельзя. Ссылка вида `https://storage.googleapis.com/<bucket>/<key>.html`.
   - `LocalDirPublisher` (по умолчанию) пишет файл в `SHARE_DIR`, а приложение раздаёт
     его по `/shared/<key>.html`. Это нужно для локальной работы и для self-hosted
     `docker compose` без IAP.
3. **Ключ — `secrets.token_urlsafe(SHARE_TOKEN_BYTES)`**, 128 бит. Ссылку нельзя угадать
   или перебрать, и в ней нет id разбора. В HTML стоит `noindex`.
4. **Приватность не ослабляется.** В снимок идёт то же, что лежит в БД: в диалоге
   собеседники названы метками, `legend` в снимок не попадает. Обсуждение с судьёй в
   снимок не входит, потому что это личная переписка пользователя.
5. **Снятие с публикации** удаляет объект и запись. Удаление разбора сначала снимает его
   с публикации. Если хранилище недоступно, разбор не удаляется (502): иначе публичная
   страница осталась бы без способа её убрать. Кэш `Cache-Control: max-age=
   SHARE_CACHE_MAX_AGE_S` ограничивает, сколько снятая страница ещё может отдаваться из
   кэшей.
6. **Рендер — в interface-слое** (`interface/share/page.py`, это представление). В
   `ShareService` (application) он передаётся функцией при сборке приложения, поэтому
   application не импортирует interface.

## Alternatives considered

1. **Публичный маршрут в самом приложении (`/s/<token>`).** Это проще всего, и ссылка
   живая. Отвергнуто: на Cloud Run IAP либо на всём сервисе, либо его нет. Пришлось бы
   поднимать второй публичный сервис с доступом к БД или ставить балансировщик с
   правилами по путям. Это больше инфраструктуры, чем у всего проекта.
2. **Скачать HTML-файл.** Инфраструктура не нужна. Отвергнуто как основной путь: файл —
   не ссылка, и на телефоне в мессенджере его открывать неудобно. Если понадобится, можно
   добавить позже: рендер общий.
3. **Клиентский рендер снимка (JSON + JS из `app.js`).** Не нужно дублировать разметку
   вердикта в Python. Отвергнуто: снимок зависел бы от JS и от версии фронтенда, а
   серверный рендер проверяется unit-тестами (экранирование, состав).
4. **Подписанные URL GCS с истечением.** Отвергнуто: срок жизни у них не больше 7 дней, а
   ссылкой делятся надолго. Отзыв через удаление объекта проще.

## Consequences

- Новая зависимость `google-cloud-storage`. Её вызовы синхронные и идут через
  `asyncio.to_thread`.
- Новая таблица `analysis_shares`. `create_all` создаёт её и на существующей БД, миграция
  не нужна.
- Сервисному аккаунту Cloud Run нужна `roles/storage.objectAdmin` на бакет снимков.
- Снимок — копия данных вне БД. Удаление разбора обязано снимать снимок (п. 5).

## Revisit when

- Захочется живой страницы, которая обновляется (например, с чатом). Тогда понадобится
  публичный read-only сервис.
- Понадобится срок жизни ссылки: lifecycle-правило бакета или подписанные URL.
