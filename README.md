# ⚖️ Rational Check — проверка здравого смысла

Цель — **найти истину, а не победителя**. Вставляешь текст или диалог — три
**рациональных аналитика** (одна команда LLM-агентов без философских школ, апологеты
рационального мышления по Манифесту здравого смысла) разбирают его независимо, потом
перекрёстно проверяют друг друга: критикуют слабые места и явно принимают рациональные
доводы коллег. **Судья** не выбирает победителя: он формулирует, что ближе всего к истине,
что доказано / вероятно / непроверяемо, какие уловки найдены, на чём аналитики сошлись и
что осталось открытым. Для **диалога** судья оценивает близость каждого собеседника к
истине, называет, что у каждого верно, и чья картина ближе всего. После вердикта его
можно **обсудить с судьёй**: переспросить, оспорить вывод, принести новый довод.

Интерфейсы: **веб** (основной), Telegram-бот, консоль. Провайдеры: **Anthropic**
(по умолчанию) и **DeepSeek**; без ключей — mock-режим.

```
Раунд 1 · Независимый разбор      🔎 Эмпирик · 🧩 Логик · ⚖️ Стилмен — параллельно, не видя друг друга
Раунд 2 · Перекрёстная проверка   Принимаю: … / Оспариваю: … / Уточняю: …
⚖️ Вердикт судьи                  что ближе всего к истине; доказано / вероятно / открыто;
                                   уловки; диалог → близость каждого собеседника к истине
```

## Запуск

### Локально (uv)

```bash
uv sync
cp .env.example .env            # впиши ANTHROPIC_API_KEY (или DEEPSEEK_API_KEY)
uv run rational-check           # http://127.0.0.1:8000
```

Без ключей приложение стартует в **mock-режиме** (заглушки вместо моделей) и говорит об
этом в интерфейсе — удобно посмотреть UI, ничего не тратя.

Другие интерфейсы:

```bash
uv run python -m debate_arena.interface.cli "текст для разбора" --rounds 2
uv run rational-check-bot        # нужен BOT_TOKEN; /check <текст> в чате
```

### Docker (web + Postgres, бот по профилю)

```bash
cp .env.example .env
docker compose up -d --build                  # http://localhost:8000
docker compose --profile bot up -d            # плюс Telegram-бот
```

### Google Cloud Run (проект `ivan-pets`)

Сервис `debate-arena`, вход через IAP, SQLite реплицируется Litestream в
`gs://ivan-pets-litestream/debate-arena` (`deploy/`), `max-instances 1`. Выкатка нового
кода сохраняет env, секреты и IAP прошлой ревизии:

```bash
gcloud run deploy debate-arena --source . --project ivan-pets --region europe-west1
```

## Конфигурация

Всё через `.env` (см. `.env.example`). Главное:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `ANTHROPIC_API_KEY` / `DEEPSEEK_API_KEY` | ключи провайдеров | — |
| `MODEL_ANALYST`, `MODEL_JUDGE` | `provider/model` | `anthropic/claude-opus-5-5` |
| `ANALYST_EFFORT`, `JUDGE_EFFORT` | глубина размышления Anthropic | `medium`, `high` |
| `DEFAULT_ROUNDS`, `MAX_ROUNDS` | раунды | 2, 3 |
| `MAX_TEXT_CHARS` | лимит текста | 20 000 |
| `LANGUAGE` | язык реплик и вердикта | русский |
| `DATABASE_URL` | SQLAlchemy async URL | локальный SQLite |
| `PUBLIC_URL` | адрес веба для ссылок из бота | — |

Полный список констант поведения с обоснованием — `SPEC.md` §7.

> Стоимость: разбор = `3 × раундов + 1` вызовов модели (7 при двух раундах). На Opus 5.5
> thinking входит в лимит токенов; бюджеты реплик — `TURN_MAX_TOKENS` / `JUDGE_MAX_TOKENS`.

## Что на фронте

- Форма: текст или диалог («Имя: реплика», режим распознаётся автоматически, есть
  переключатель), необязательный вопрос «что именно проверить», глубина (1–3 раунда),
  выбор модели из доступных по ключам, счётчик символов, ⌘/Ctrl+Enter.
- Живой ход по SSE: чипы аналитиков со статусом «думает / готово», раунды, карточки
  реплик с размеченными блоками **Принимаю / Оспариваю / Уточняю**, таймер.
- Вердикт: что ближе всего к истине, шкала рациональности материала, уверенность судьи,
  «установлено / вероятно / неопределённо», утверждения со статусами, уловки с цитатами,
  сильнейшая версия · что изменит вердикт · что из этого следует, на чём аналитики сошлись
  и что осталось открытым. В диалоге — карточки собеседников с близостью к истине, что у
  каждого верно и где ошибка. Аналитики не оцениваются: они ищут истину сообща.
- **Обсуждение с судьёй** под вердиктом: вопросы и возражения, ответ — той же моделью,
  что выносила вердикт, со всем разбором в контексте. Судья меняет оценку только под
  весом доводов и говорит об этом явно («Пересматриваю: …»); на нажим без аргументов не
  уступает. Сохранённый вердикт не переписывается, переписка хранится с разбором и входит в
  Markdown-экспорт. Лимит — 20 сообщений на разбор (`JUDGE_CHAT_MAX_MESSAGES`).
- История разборов в боковой панели, удаление, ссылка на разбор, копирование в
  Markdown, скачивание JSON, «разобрать снова», тёмная тема, мобильная вёрстка.

## Приватность собеседников

В режиме диалога настоящие имена **не уходят ни в модель, ни в базу**: реплики
переписываются как «Собеседник А: …», упоминания имён внутри реплик (включая падежи)
заменяются на метки. Соответствие «метка → имя» возвращается один раз в ответе на запуск
разбора и хранится только в вашем браузере: кнопка «Показать настоящие имена» подставляет
их локально. Сообщения судье в чате анонимизируются так же: браузер присылает легенду
вместе с сообщением, сервер заменяет имена метками и легенду не хранит. Отключается `ANONYMIZE_PARTICIPANTS=false`. Для обычного текста имена не
распознаются (это задача NER, не в scope).

```
src/debate_arena/
├── config.py          pydantic-settings (значения SPEC §7)
├── main.py            FastAPI app, lifespan, раздача фронтенда
├── domain/            schemas (Verdict, AnalystSpec), analysts, prompts (Манифест), ports
├── application/       flow (раунды + судья), service (фоновые запуски, события, персист)
├── infrastructure/    llm/ (anthropic, deepseek, mock, factory); db/ (models, session, repo)
└── interface/         api/ (routes, SSE), web/static/ (index.html, app.js, styles.css), bot/, cli.py
```

Правило: `interface → application → domain ← infrastructure`. Решения — в `docs/adr/`:
провайдеры напрямую через SDK (001), аналитики и протокол (002), web/SSE (003), слои (004),
обсуждение вердикта с судьёй (005).

## Cut scope

- **Потоковые токены внутри реплики** — SSE отдаёт реплику целиком; на Opus 5.5 с
  thinking реплика идёт 20–60 с, индикатор «думает…» это покрывает. Чтобы добавить:
  `messages.stream` в `AnthropicProvider` + событие `delta`.
- **Серверный fallback при отказе модели** (beta `server-side-fallback`) не включён:
  отказ показывается как ошибка разбора. Включить — флаг в `AnthropicProvider`.
- **Веб-поиск / проверка по источникам** — аналитики работают только с текстом и обязаны
  писать «не могу проверить». Нужен tool use у провайдера.
- **Аутентификация и квоты** — инструмент личный.
- **Eval качества промптов** — измерен только крен рамки Манифеста (`evals/frame_bias`,
  1 повтор); различимость линз и качество вердиктов на golden set не измерены (ADR-002,
  Revisit when).
- **Синхронизация со скиллом `common-sense`** — пп. 1, 3, 6 Манифеста в промпте сужены до
  утверждений о фактах и теперь расходятся с первоисточником (ADR-002, ревизия о рамке).
- **Чат с судьёй в боте и CLI** — только веб. В боте естественно сделать ответом
  (reply) на сообщение с вердиктом: `JudgeChatService.ask` уже общий.
- **Потоковый ответ судьи в чате** — ответ приходит целиком одним POST (ADR-005).
- **Живой замер чата** — время ответа судьи на Opus 5.5 не измерено; оценка по реплике
  аналитика (18–30 с).
- **Alembic** — схема создаётся `create_all`; миграции подключить при первом изменении схемы.
